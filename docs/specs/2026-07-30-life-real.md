# 生命遊戲時鐘 v2：改成真的模擬（life）

2026-07-30

只改 `life/`。取代 [2026-07-29-life-clock.md](2026-07-29-life-clock.md) 的第一版。

一句話：整片場只跑 B3/S23，沒有任何一格被按住或被擦掉；每分鐘從場外丟進滑翔機，
舊數字是**真的被撞掉**的，新數字是**真的被撞出來**的。

---

## 一、為什麼要重寫

第一版是假的，而且是刻意假的：

- **斥力場**：每演化一代就把數字的 block 強制寫回 1、把外圈強制清成 0。
  數字不是活在規則裡，是每一代被畫上去的。
- **錄影倒放**：換字動畫是把「目標數字 + 噪點」往前跑 N 代錄下來、播放時倒著放。
  畫面上看起來像混沌聚合成數字，其實時間是反的。

兩招都是為了迴避同一件事：生命遊戲是混沌的，**不可能靠隨機演化碰運氣跑出 `12:34`**。

v2 換一條路：不靠運氣，靠**建構**。數字的每一塊都用已知的反應精確地拆掉、精確地蓋回來。
規則從頭到尾只有 B3/S23，時間只往前走。

## 二、兩個反應（用真的模擬窮舉出來的）

數字的每個點陣亮點都是一個孤立的 2×2 block —— B3/S23 下的靜物，放著不動就永遠不變。
所以「換字」只需要兩種操作：**刪掉一個 block**、**生出一個 block**。兩個都有現成的滑翔機反應：

| 配方 | 內容 | 結果 |
|---|---|---|
| `R_DEL` | 1 隻滑翔機正面撞上 block | 兩邊同歸於盡，該區全空，零殘骸 |
| `R_ADD` | 2 隻滑翔機對撞（一隻往東南、一隻往西南） | 留下一個 2×2 block，位置固定 |

窮舉方式：把 block 放在原點，滑翔機從 4 個方向 × 4 個相位 × 垂直偏移掃過去，
跑真的模擬到收斂，撿出「最後全空」的組合；生成則掃兩隻滑翔機的方向、相位與相對位移，
撿出「最後剛好是一個 2×2 block」的組合。消滅命中 48 組、生成命中 2680 組，各挑最短的一組。

配方在程式裡寫成「相對於目標 block 左上角的 5 個 cell + 航向 + lead（注入後第幾代反應完成）」。
沿 −航向退 k 格就等於提早 4k 代發射，所以**同一組配方可以從任意遠處發射**，
發射點拉到畫面邊緣也一樣成立。南邊來的版本用上下鏡射生成 —— block 對 `y → 1−y` 對稱、
規則也對稱，所以鏡射過的配方一定同樣成立，不必再搜一次。

## 三、航道不會互相打到（這是解出來的，不是試出來的）

一次換字最多要 19 隻拆字滑翔機 + 38 隻蓋字滑翔機，四位同時換就是 228 隻。
要讓它們互不干擾，靠兩件事。

### 1. 撞到別的 block：靠順序

北半邊（列 0–3）的滑翔機一律從上方來，南半邊（列 4–6）從下方來。於是：

- **拆**：由近而遠。北半邊從第 0 列往第 3 列拆，南半邊從第 6 列往第 4 列。
  航道穿過的點陣位置一定更靠外，早就拆掉了。
- **蓋**：由遠而近。北半邊從第 3 列往第 0 列蓋，南半邊從第 4 列往第 6 列。
  航道往外穿過的列都還沒蓋，所以是空的。

這是幾何上成立的，不是碰運氣。拆完最後一隻落地之後才發射蓋字的第一隻（`PHASE_GAP`），
兩個階段不重疊。

### 2. 滑翔機互撞：靠一條常數

蓋字的兩隻一隻往東南、一隻往西南。任取兩個目標點 A、B，
**A 的東南隻與 B 的西南隻，外框左上角的 y 差在整段飛行中是個常數**：

```
Δy = ((32 + DT_ADD)·Δr − COL_STAGGER·Δc + 8) / 4
```

（`Δr`、`Δc` 是兩個目標點的點陣列差與欄差。）只要對所有 `(Δr,Δc) ≠ (0,0)` 都讓
`|Δy| ≥ 6`，兩隻的細胞之間永遠空得下兩排，半路上撞不到 —— 只有 `(0,0)`，
也就是本來就要湊成同一個 block 的那一對，會相遇。

門檻是 6 不是 4：滑翔機一個週期裡外框會漂 1 格、兩邊各漂一次，再加上中間那排空格
會同時看到兩邊的細胞而**誕生**新細胞。4 和 5 都實測會爛（第一次做就是踩在 4）。
`DT_ADD=128`、`COL_STAGGER=32` 是滿足條件裡最短的一組。

同向同航道的兩隻間距是 `|32+DT−COL|/4`，拆字那邊是 `|32−DT_DEL|/4`；同向的漂移一致
不用加保險，`≥ 5` 就夠，所以 `DT_DEL = 56`。

四位數字**完全同相**（`DIGIT_STAGGER = 0`）。錯開反而會讓上面那條常數失效；
同相時相鄰位的 x 差 62 不是 8 的倍數，兩位之間根本共不到一條航道。

## 四、版面

格距 8（block 2 + 空隙 6）。空隙留到 6 是為了讓滑翔機從 block 之間的對角線穿過去
而不打到旁邊。一位數字 34×50 格，橫式四位並排（間距 28，冒號那格 40），
直式 2×2 排（列距 40）。

直式時上下兩排數字各分半個列距的領空，中線再各退 3 格 —— 不然上排往下丟的
和下排往上丟的會在中間對撞。發射距離在領空裝得下的前提下盡量拉遠（最多 22 格）。

## 五、其他

| 項目 | 說明 |
|---|---|
| 場 | 稀疏模擬：只走訪活細胞與其鄰居，成本只跟人口有關（閒置約 470 個細胞） |
| 邊界 | 最外兩格是吸收層。萬一有東西飛出畫面就讓它出去，不要黏在邊上 |
| 背景 | blinker／toad／beacon／beehive／boat／loaf／tub，全是貨真價實的物件。只放在「所有可能的航道」都碰不到的地方，所以永遠不會被撞掉 |
| 秒針 | 閒置時 1 代／秒，震盪器就是秒針。數字是靜物，所以不動 |
| 換字 | 全盤加速到 320 代／秒，一次換字 2.8 秒（四位同時換也一樣） |
| 亮塊 | 只有「四格都真的活著」的 2×2 才畫成白色。畫面上亮的東西，是場上真的長出來的東西 |
| `dataset.shown` | 蓋完之後先驗證四格都在，才寫入。驗不過就補上去並把 `heals` 加一 |
| reduced-motion | 不播滑翔機，直接換 block；閒置時也不演化 |

`heals` 是這次改版的驗收指標：**只要有任何一位不是靠滑翔機撞出來的，它就會 +1。**
橫式與直式各跑完整一天 1440 分鐘，`heals` 全程為 0。

## 不做的事

- 不做多規則切換、不做滑鼠互動播種。
- 只換到的那一位才動，沒變的位一格都不碰。
- 換字時整位數字先拆光再蓋回來（不是只補差異）：順序保證才成立，程式也短。

## 驗收條件

1. `python3 tools/check.py` → 全綠。
2. `node tools/simulate.js life/index.html` → 通過。
3. 自帶的驗證：橫式 1200×750 與直式 420×900 各跑 1440 分鐘，`heals === 0`。
4. 換字歷時 2.8 秒，遠低於 `simulate.js` 的 6000 ms 上限。
5. `life/sw.js` 的 `VERSION` 升到 `'life-v2'`。
