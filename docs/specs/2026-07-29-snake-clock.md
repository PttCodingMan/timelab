# 貪食蛇時鐘（snake）

數字是一條蛇的身體。換分鐘時蛇不消失：頭從舊數字的終點鑽出去、沿新數字的筆順爬完，
尾巴同時從舊路徑收回。長度不夠就吃食物補。

- id: `snake`
- name: 貪食蛇時鐘
- tagline: 蛇身就是筆畫。換分鐘頭鑽出去爬成新數字，尾巴從舊路徑收回，長度不夠就沿路吃
- accent: `#8bac0f`
- tags: `["arcade", "canvas", "pwa"]`

## 1. 格線與版面

整個錶面是一片格子。每位數字佔 **5 欄 × 9 列**，四位橫排：

```
[HH 十位 5] [空 1] [HH 個位 5] [冒號 2] [MM 十位 5] [空 1] [MM 個位 5]
```

共 24 欄 × 9 列。冒號是兩顆靜止的點（在冒號欄的 y=2 與 y=6），**每秒閃一次**——
秒由冒號負責，蛇不管秒。

格子邊長由畫布尺寸算出來（`min(w/24, h/9)` 再留邊距），錶面置中。

## 2. GLYPH 表（本鐘的核心資料）

每個數字 = **一條在格子上連續（4 鄰接）、不重複踩格的路徑**。
標準點陣字不能用：`4` 有分叉、`8` 有交叉，蛇會咬到自己。以下是驗過的字形，
座標 `(x, y)`，x 0–4（左→右），y 0–8（上→下）。

路徑的頭尾允許「貼著自己的身體」收尾（例如 `0` 的尾巴停在起點旁邊），
視覺上就是閉合的——這是能畫出完美 `0`、`8`、`6`、`9` 的關鍵。

（一筆畫的 `3` 在幾何上不存在——它有三個自由端點）。其餘九個字都是標準一格粗筆畫。

## 3. 換場

只有**數字真的變了**的那一位會動；沒變的那位靜止不動。

### 路線

`R = 過渡段 + 新字路徑`

過渡段用 **BFS** 從舊字終點走到新字起點，限制在**這一位自己的 5×9 區域內**，
不得穿過當下的蛇身。

### 每 tick 的規則

1. **頭**沿 `R` 前進一格。若下一格仍被自己的身體佔住 → **原地等一拍**（尾巴照收，
   身體變短，那格遲早會空出來）。這保證一定會通，不會死鎖。
2. **尾巴**每 tick 收一格。
3. **食物**：場上最多一顆，生在蛇即將經過的路線上（頭前方 3–5 格）。頭吃到 → 尾巴
   暫停一拍（身體 +1）。還需要更長就再生一顆。

需要變長 `newLen - oldLen` 格，就是要吃 `newLen - oldLen` 顆——這條等式自然成立，
不用另外配速。需要變短時不生食物，尾巴偶爾連收兩格。

**收尾不變式**：動畫結束時 body 必須**恰好等於新字路徑**（同一組格子、同順序）。
頭鋪完新字最後一格時，尾巴必須剛好停在新字第一格。

### 首次載入

沒有舊字，蛇從新字起點長度 0 逐格長到滿，像遊戲開場。

### 節奏

一格一拍，約 80ms／拍，整段 2–3 秒跑完。同時要換的位數（`09:59 → 10:00` 四位全換）
各自獨立跑，互不等待。

## 4. 視覺

Nokia 單色 LCD。

- 底：`#c7d47a`
- 未點亮的格子：底色上淡淡印一層 `#b8c66c`（LCD 的「看得見的空格」）
- 蛇身：`#2f3a10`，方格硬邊、**零圓角**、格與格之間留 1px 縫（像素感）
- 頭：同色方塊，中間挖一個約 1/3 大小的底色小方塊當眼睛，朝行進方向偏移
- 食物：比格子小一圈的實心方塊
- 冒號：兩顆與蛇身同色的點，每秒閃

不要漸層、不要發光、不要陰影、不要 easing 補間——一格一格跳，這是 LCD。

## 5. 四個約定（README §四個約定）

1. `?embed=1` → 隱藏 UI 只留錶面，且不註冊 service worker
2. cache 名 `snake-v1`
3. 四位數字**全部畫完的那一幀**才寫 `document.documentElement.dataset.shown = 'HHMM'`；
   換場進行中維持舊值（此時畫面上是扭動的曲線，不是可讀的數字）
4. manifest 的 `start_url` / `scope` 都寫 `"./"`，另給明確 `id`

## 6. 自檢

`GLYPH` 表載入時跑一次 assert，字形寫錯當場炸：

- 每條路徑相鄰兩格必須真的 4-鄰接（曼哈頓距離 = 1）
- 同一條路徑不得重複踩同一格
- 所有座標落在 `0 ≤ x ≤ 4`、`0 ≤ y ≤ 8`
